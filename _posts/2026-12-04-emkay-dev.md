## What got me hooked

What got me hooked on Mycroft back then was making skills. Write a few
sentences and a bit of Python, say the sentence, and hear it answer. Then
change something and see why it worked, or why it did not.

I wanted that loop to be as short as possible. So I got VS Code running on
the device itself, and built skills directly on my Picroft. Edit, restart
the skill, talk to it. It was the best way I found to learn how the whole
thing fits together.

That setup took a Pi, a microphone that worked, a speaker, and an evening
of getting VS Code to run on it. Not a good first step for a newcomer.

## Emkay Dev

[Emkay Dev](https://dev.emkay.ai) is that loop, with nothing to install.
It is VS Code in the browser ([vscode.dev](https://vscode.dev)) with the
Emkay Dev extension. Emkay, a full OVOS, opens in a panel next to your
code and runs your skill.

![dev.emkay.ai](/assets/blog/emkay-dev/dev-emkay-ai.png)

It is the real VS Code, with the normal Marketplace (and Open VSX for the
open editors). I like that a newcomer learns the real tools from day one,
and not a toy editor that they must leave later. It also works in VS Code
on your own PC and in Codespaces.

## From template to answer

1. **Emkay: New skill.** Pick a template, give it a name, and you get a
   working skill in the open folder.
2. **Run the skill in Emkay.** Emkay opens next to the code and loads the
   skill from its files, the same way `ovos-core` loads a skill from a
   folder. Its requirements are installed in Emkay.
3. **Type to Emkay**, and hear the answer. Every time you save, the skill
   runs again.

![VS Code with Emkay next to the code. The output shows what was said, which intent matched, and what Emkay answered](/assets/blog/emkay-dev/vscode-emkay.png)

The templates are real, working skills, each in its own repo. There is a
plain "hello" skill, a quiz with `get_response` and `ask_yesno`, pictures
on the screen, a web API (air quality), your own questions and answers for
common query, a fallback that suggests what you may have meant, a radio
skill for OCP, and a reading provider. There is also a PHAL plugin template
for quiet hours, because plugins are part of OVOS too. All templates speak
all of Emkay's languages.

The microphone is not available inside a VS Code panel, so you talk by
typing. Sound out works. Emkay in the panel has its own storage, so it
never touches the Emkay you use day to day.

## One click, more languages

OVOS speaks many languages, and a skill should too. **Emkay: Add
language** takes the skill's English (`locale/en-US`) and translates it
into one of Emkay's languages. It runs on your device, with the same
translation models that [ovos-localize](https://github.com/OpenVoiceOS/ovos-localize)
uses. It keeps the `{slots}` and the `(a|b)` groups of the intent files
intact, and it writes golden utterances for the new language, so you can
test it at once.

It is a machine's draft, and Emkay Dev says so. The output lists what was
left out and why, and the commit message marks it as machine translated,
the same way ovos-localize does. Then someone who speaks the language can
read it and fix it.

## See what happens

The output shows what you said, what Emkay answered, and the log: your
skill's lines, the lines about loading skills and matching intents, and
every warning and error.

![What's happening: what Emkay heard, which skill took it, and what it answered](/assets/blog/emkay-dev/whats-happening.png)

"What's happening?" is a web version of what
[ovos-tui-client](https://github.com/andlo/ovos-tui-client) shows in the
terminal. It tells you which skill took the sentence, or which fallback,
and what it answered. When a skill does not trigger, this is where you see
why.

## Test it

**Emkay: Test the skill** runs the skill's golden utterances in VS Code's
Testing view. You get a check mark when a sentence reaches your skill. You
get a cross, with the skill that took it, when it does not. The judge is
[ovos-routing-judge](https://github.com/emkay-voice/ovos-routing-judge),
the same one that ovos-tui-client and the store's nightly test use. So a
sentence passes or fails the same way in all three places.

## Show it, and look at others

When you are happy with a skill, **Show in See my skill** adds it to
[the gallery](https://dev.emkay.ai/gallery/). It only does that when you
ask, and it puts a topic on your public GitHub repo. Others can try your
skill in their Emkay, or make their own copy and change it. A skill made
from a template never shows up there by itself.

This is not the store. Nobody publishes to the store. A skill gets into
the store because it is well made and passes the nightly test. The gallery
is the loose, fun place: "look what I made".

The store also points back here. Every skill in
[store.emkay.ai](https://store.emkay.ai) has a button that opens its code
in Emkay Dev. Find a skill you like, open it, change a sentence, and hear
your version answer.

## Why this matters for OVOS

OVOS lives on its skills. Many people who made a Mycroft skill did it
because it was fun and easy to try.

![Top authors and organisations in the Klondike Mercantile skill directory](/assets/blog/emkay-dev/klondike-authors.png)

The number of people who make skills and plugins for OVOS is small. You
can see it in the stats of the
[Klondike Mercantile](https://andlo.github.io/ovos-klondike-mercantile/)
directory. It lists 585 skills and components from 56 GitHub accounts.
Most of them come from a handful of accounts, and OpenVoiceOS itself is by
far the largest. More than half of the accounts have a single entry.

I think part of the reason is the first step. If getting started is easy,
and it teaches the right way to do things from the start, more people may
try. And with more people come more fun, odd and good alternative skills
and plugins. I hope Emkay Dev can be that first step, for people who
would never set up a Pi for it.

The skills you make are normal OVOS skills. They install on raspOVOS, a
Mark II, a container or anything else that runs OVOS, exactly like any
other skill. Emkay is just the quickest place to try them.

Go to [dev.emkay.ai](https://dev.emkay.ai), make a skill, and tell me what
broke. Emkay is an early alpha, and that feedback is what makes it better.
Questions and show and tell are welcome in
[the Emkay discussions](https://github.com/emkay-voice/emkay/discussions)
or in the OVOS chat.
